## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local repo -> Qollab upload zip | Only allowlisted files leave the machine |
| local repo -> public GitHub | `gh repo create --public --push` publishes all tracked files and commit metadata; executed only by the builder at the checkpoint |
| Qollab page -> IonQ cloud | One job per run, submitted with the visitor's or owner's credits |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04 | Information disclosure | scripts/package_qollab.sh zip contents | mitigate | Explicit allowlist (never `zip -r .`), plus a check that fails on `node_modules`, `.env`, `.venv`, `.planning`, `web/`, `__pycache__`, `.DS_Store` in `zipinfo -1` output |
| T-01-05 | Information disclosure | GitHub publication | mitigate | Executor only prepares commands and runs the `git ls-files` secret scan (stops on any match); the public repo is created by the builder at the blocking checkpoint after reviewing the scan; acceptance criterion asserts `git remote` is empty after Task 1. No keys exist in code because Qollab injects `backend`. Commit author metadata becoming public is accepted as standard for a public repo |
| T-01-06 | Denial of service / cost | IonQ probe runs at checkpoint | mitigate | Probe uses the remote simulator only, one job per run, shots allowlisted to <= 4096; credits checked before any hardware use (deferred to Phase 4 decision) |
| T-01-SC | Tampering | `npm ci` in packaging | mitigate | Installs exactly the committed lockfile from Plan 02 (all four packages [OK] in the Package Legitimacy Audit) |
