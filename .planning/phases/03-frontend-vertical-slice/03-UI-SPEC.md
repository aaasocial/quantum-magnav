# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Sources: 03-CONTEXT.md D-01..D-16 (locked), REQUIREMENTS.md (UI-01/02/03/05, A11Y-01/02), research/STACK.md, docs/QOLLAB_FINDINGS.md, web/src/App.jsx + app.css (Phase 1 baseline), and data/precomputed_run.json (field shapes checked 2026-10-10). Anything marked **[R-decision]** was not covered upstream and was decided here (autonomous mode) to stay consistent with the locked decisions.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (shadcn gate: not initialised. Under autonomous mode the choice is no shadcn. Reasons: no Tailwind in the project, the Qollab bundle is capped at 2 MB per file with only one `main.css`, and the deadline is Oct 11) |
| Preset | not applicable |
| Component library | none. Use native HTML controls (`select`, `input[type=checkbox]`, `input[type=range]`, `button`, `details`, `table`), styled with plain CSS in `web/src/app.css` |
| Charts | recharts **3.10.1** exact pin (signal panel only). The map uses an HTML `<canvas>` plus an absolutely positioned `<svg>` overlay, with no map library (D-09) |
| Colormap | `interpolateCividis` from d3-scale-chromatic **3.1.0** exact pin (tree-shaken named import) **[R-decision]** |
| Icon library | none. Use inline SVG for the drone glyph, the jam marker and the play/pause glyphs (each `aria-hidden="true"`, always paired with visible text) |
| Font | system stack: `system-ui, -apple-system, "Segoe UI", Roboto, sans-serif` (D-08); numerals use `font-variant-numeric: tabular-nums` |
| Theme | dark only (D-05). Set an explicit background on `:root` because the page sits in Qollab's sandboxed iframe over a dark site |

All colours, spacing and type sizes are CSS custom properties declared once on `:root` in `app.css`. JS (canvas, recharts) reads series colours from one shared module, `web/src/theme.js`, which mirrors the CSS variables. Hex literals appear only in `app.css` `:root` and `theme.js`.

## Spacing Scale

Declared values (all multiples of 4):

| Token | CSS variable | Value | Usage |
|-------|--------------|-------|-------|
| xs | `--space-1` | 4px | Gap between an icon and its label, gap between a legend swatch and its text, badge inner vertical padding |
| sm | `--space-2` | 8px | Gap between controls inside a field group, badge horizontal padding, table cell vertical padding, legend item gap |
| md | `--space-3` | 16px | Page side padding, control bar item gap, panel inner padding, table cell horizontal padding |
| lg | `--space-4` | 24px | Gap between the map column and the signal column, gap between page sections |
| xl | `--space-5` | 32px | Space above the footer, space above the results section |
| 2xl | `--space-6` | 48px | Not used in Phase 3; reserved |

Fixed component dimensions (all multiples of 4):

| Element | Value |
|---------|-------|
| Control height (select, button) | 36px (minimum target size; meets WCAG 2.2 SC 2.5.8, which asks for at least 24px) |
| Checkbox hit area (label + box) | at least 32px tall |
| Range slider track | 4px tall; 16px thumb; 36px tall hit row |
| Map canvas max height | 520px |
| Signal chart height | 240px |
| Residual chart height | 140px |
| Colorbar | 160px × 12px |
| Drone glyph | 24px |
| Jam marker | 16px |
| Page max width | 1200px |

Exceptions: 1px borders, the 2px focus outline offset, 3px focus outline width, and chart stroke widths (2px series, 1px grid) are hairline values outside the scale.

### Heatmap (D-07)

- Valid cells: `interpolateCividis(normalised nT)`. The domain is the 2nd–98th percentile of valid `map_preview.nT` for the selected line (clamped), computed once per line.
- Invalid cells (`valid[i] == 0`): base `#24282F` with 45° hatch stripes `#3A3F47`, 1px every 4 px (canvas pattern).
- Legend under the map: a 160×12 px colorbar with ticks at the domain minimum, 0 nT (if inside the domain) and the maximum, labelled e.g. `-600 nT`, `0`, `1,400 nT` (rounded to 100). A 12×12 hatched swatch is labelled "No survey data".

## Layout and Responsive Rule

**Page structure (top to bottom), inside `<main class="page">` with max width 1200px, centred, and side padding `--space-3`:**

1. **Header:** `h1` "Quantum MagNav: holding position without GPS", then a one-paragraph intro (Body, muted).
2. **Control bar** (`<section aria-label="Playback controls">`, surface panel, flex-wrap, gap `--space-3`), in this order:
   Flight line select → Sensor select → Map track select → Play/Pause button → Scrub slider (grows to fill the row) → time readout → Speed select → Run live in-page button.
   Below it, in its own row, the **Signal series** `fieldset` with checkboxes: truth is shown as a non-interactive "always shown" legend item and is not a checkbox.
3. **Status strip** (`<section aria-label="Run status">`, one row, wraps): mode badge, then the live status/progress message, then the provenance line (muted, Label size).
4. **Jam banner** slot: a fixed-height region (min-height 40px, so the layout does not jump). It is empty before the jam and shows the banner once the current index is at or after `jam.display_index`.
5. **Main grid:** map panel (`MapView`) and signal panel (`SignalPanel`).
6. **Results section:** h2 "Navigation accuracy", metrics mini-table, then the text alternatives (`details`).
7. **Footer** (kept from Phase 1).

**Responsive rule:**
- `@media (min-width: 900px)`: main grid `grid-template-columns: minmax(0, 1fr) minmax(0, 1fr)`, gap `--space-4`; map on the left, signal panel on the right (D-01/D-03).
- Below 900px: a single column, map first, signal panel stacked below.
- The map canvas fills its column width. Height = width × (y-extent ÷ x-extent of `map_preview`), capped at 520px with the aspect ratio preserved (letterboxed with `--color-surface`). The backing store is scaled by `devicePixelRatio` and redrawn on `ResizeObserver`.
- recharts uses `ResponsiveContainer width="100%"` with fixed heights (240 / 140).
- Below 600px the control bar items take full width (`flex-basis: 100%` on the slider row).

**Data mapping rules (from the verified artifact shape):**
- Line arrays (`t`, `truth.*`, `dead_reckoning.*`, `estimates[sensor][denoiser].{x,y,signal_nT}`) share one display index space (1264 points for 1003.02, 1499 for 1007.06). The player indexes everything by this display index.
- Jam index on the display axis = `jam.display_index`; jam time = `jam.t_s`.
- `metric_start_index` is in **raw-sample** space. Convert it to time: `metric_start_t = metric_start_index × jam.t_s ÷ jam.index`, which gives 1006 s for 1003.02. The magnetic-only segment on the display axis is the first `i` with `t[i] >= metric_start_t` onwards.
- RMSE badges and the mini-table read `lines[i].metrics[sensor][denoiser].signal_rmse_nT` / `mean_err_m` / `cep50_m` / `cep95_m` / `pct_under_556`, and `lines[i].metrics.dead_reckoning`. The UI does not recompute metrics, so precomputed and live runs show identical numbers, provided the live `run_line` returns the same `metrics` block.
- Residual series = `signal_nT[i] − truth.anomaly_nT[i]`, plotted only for `i >= metric start`.
- Live mode returns one `lines[i]` entry for one sensor with denoisers `raw, lowpass, tl, quantum`. Series missing from the result (`tl_currents`, `krr`) show their checkboxes disabled, with help text (see Copy).

## Interaction Contract

### Default state on load (CONTEXT specifics)
Line 1003.02, sensor Mag 5 (`default_sensor`), map track TL, visible series truth + raw + TL, paused at index 0, speed 60×, mode badge "precomputed replay", and the mini-table already filled. The paused hint is shown in the status strip.

### Playback
- Play advances `t` at `speed × wall-clock seconds` (10× / 60× / 300×; default 60×). The index is the last `i` with `t[i] <= playTime`.
- At the end: playing stops, the button returns to "Play", and the next Play restarts from index 0.
- Changing the line or sensor pauses playback, resets to index 0, keeps the series toggles and speed, and updates the mini-table and RMSE badges.
- Scrubbing while playing keeps playing from the new position.

### Keyboard (D-11)
| Key | Context | Action |
|-----|---------|--------|
| Tab / Shift+Tab | everywhere | Moves through controls in visual order (DOM order matches the layout order above; no positive `tabindex`) |
| Space | focus on `body`, the map figure or the signal figure (not inside a select, checkbox, button or `details` summary, which keep native Space) | Toggle play/pause |
| ArrowLeft / ArrowRight | focus on the scrub slider, or on `body`/figures | Step back/forward one navigator window (10 s of flight time; the nearest display index) |
| PageDown / PageUp | slider | Step back/forward 60 s |
| Home / End | slider, or `body`/figures | Jump to the first / last index |
| J | `body`/figures | Jump to 5 s before the GPS jam **[R-decision]** |

The slider intercepts arrow keys in `onKeyDown` (`preventDefault`) to apply the 10 s window step. Global shortcuts are a `keydown` listener on `document` that ignores events whose target is a form control or `[contenteditable]`. The map and signal figures have `tabIndex={0}` so shortcuts work after clicking or focusing them; each shows the focus ring.

### Reduced motion (D-12)
With `matchMedia('(prefers-reduced-motion: reduce)')` (listen for changes):
- The playback clock still runs at the chosen speed, but the rendered index updates **once per second of wall time** (stepped), not every frame.
- No CSS transitions or animations anywhere (`@media (prefers-reduced-motion: reduce) { * { transition: none; animation: none; } }`).
- Live progress uses a static text stage counter instead of an animated indeterminate bar.

### Live mode and fallback (D-13..D-16)
1. "Run live in-page" is enabled only when `qBackend` exists and no live run is in flight. Clicking it pauses playback and sets the mode badge to "computing in-page…".
2. Staged progress messages appear in the status strip and are announced: stage *n of 4*.
3. Success: the result replaces only the selected line × sensor data, the index resets to 0, the badge reads "computed in-page", and the paused hint is shown.
4. Failure (any exception, `ok: false`, or 90 s timeout): the badge reverts to "precomputed replay", the precomputed data for the same line × sensor is shown with **identical visuals**, a danger notice gives the reason in the status strip, and `console.error` logs the full error. The Run live button stays enabled so the user can retry.
5. Changing the line or sensor while in "computed in-page" mode returns to precomputed for the new selection (the badge updates).
6. `backend.run` is never called in Phase 3 (D-16).

### Loading, empty and error states
| State | Where | What renders |
|-------|-------|--------------|
| Artifact loading | Map and signal panels | Panels at final size with the text "Loading precomputed flight…" centred (no spinner animation) |
| Artifact load error | Above the main grid | Danger notice (copy below); controls disabled except the series fieldset |
| No series toggled (truth only) | Signal panel, below the legend | Muted note (copy below); truth stays drawn; the residual chart shows its empty note |
| Series unavailable in live result | Series fieldset | Checkbox disabled, with the help text linked by `aria-describedby` |
| Before the jam | Error readout | "GPS available" state |
| Jam to metric start | Error readout | "Collecting first map-matching window" state |
