# Phase 2 Plan 03: D-19 Fluxgate Selection, RunArtifact v1 and Acceptance Summary

The Tolles-Lawson fluxgate and ridge lambda are now picked per sensor by 5-block cross-validation on calibration line 1006.08 only. The CV keeps flux_a for both sensors, but chooses lambda 0.1 for Mag 5 and 0.01 for Mag 4 instead of 1e-4. With that, the Mag 5 TL track holds on both held-out lines. `main.py` now also writes a validated 1.04 MB RunArtifact v1, prints all seven D-17 acceptance checks (**7/7 PASS**) and saves four figures under 200 kB each. The README cites the dataset and documents how to reproduce the run.

## What was built

- **Task 0, D-19 (737109b):** `select_tl_config(cal, cal_target, mag_key, ...)` in `magnav/classical.py` searches flux_a..flux_d x the 7-value lambda grid jointly. It uses 5 contiguous blocks of 1006.08 (1678 samples, about 335 per block) and bandpasses each training segment on its own. The score is the full-band out-of-block RMSE against `mag_1_c`, with the offset fitted on the training blocks. The pipeline calls it once per sensor with `cal_sensors, cal_target`. The chosen fluxgate feeds TL, TL+currents (lambda by the same CV with the fluxgate fixed) and the KRR/quantum `kernel_features`. The selection, CV score and full CV table are in `config["tl"][sensor]["selection"]`, printed by `main.py`, stored in the artifact provenance, and summarised in the README "Method notes".
- **Task 1 (8dd5b17):** `magnav/artifact.py` builds RunArtifact v1: schema_version 1, both sensors, six denoisers, truth, DR, int16 map previews (107x117 and 139x156), per-window ncc/accepted, metrics, and provenance with the D-19 selection. It uses one shared downsample index per line (1264 and 1499 points). `main.py` writes and validates it, and replays the artifact on `emscripten`. `package_qollab.sh` ships it.
- **Task 2 (12b71a0):** `acceptance_checks` (7 checks) is stored as `artifact.acceptance` and printed as an ACCEPTANCE block. `magnav/figures.py` draws the four PNGs (cividis map, Okabe-Ito colours plus distinct line styles, grey for cells without survey data). The README gains a "Data and reproduction" section.

## D-19 selection (calibration line 1006.08 only)

| Sensor | Fluxgate | Lambda | CV RMSE | Runner-up fluxgate (best lambda) | TL+currents lambda |
|---|---|---|---|---|---|
| mag_5_uc | flux_a | 0.1 | 18.3 nT | flux_b 25.3 nT | 1e-4 (CV 110.7 nT) |
| mag_4_uc | flux_a | 0.01 | 86.8 nT | flux_c 128.5 nT | 1e-4 (CV 112.7 nT) |

The fluxgate is unchanged from 02-02. The lambda changed because the 5-block full-band CV prefers more regularisation than 02-02's in-band 70/30 split did. 02-02's diagnostic configurations B and C (held-out-informed) were not used. No threshold or other parameter was touched.

## Deviations from Plan

### Additions / adjustments

**1. [Task 0, builder decision D-19] Calibration-only fluxgate/lambda selection added before the plan's tasks.** Described above (737109b).

**2. [Rule 2 - Correctness] TLDenoiser's default lambda selection switched to the D-19 CV.** TL+currents (and any `TLDenoiser` with `lam=None`) now uses the same calibration CV, so "lambda is selected the same way" holds for every TL variant. `test_real_tl_improves` still passes unchanged.

**3. [Structure] Figure code is in `magnav/figures.py` instead of inline in main.py.** It plots from the artifact, so the figures show exactly what the player replays. It ships in the zip as an inert module (matplotlib is imported lazily).

**4. [Lint] `int(round(...))` -> `round(...)` (RUF046) and `operator.ge/gt/lt` instead of lambdas.** No behaviour change.

**5. [Plan text] The plan says "six named checks" but lists seven.** All seven are implemented, and the gate reads "7/7".
